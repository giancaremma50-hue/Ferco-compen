# Portal de Compensaciones — Ferco Cerámica

## Contexto
Portal web interno para centralizar solicitudes de análisis de compensación. Actualmente el proceso ocurre de forma dispersa; el portal lo concentra en un kanban, con formulario estructurado, comentarios, archivos y notificaciones en tiempo real. Stack: Next.js 14 App Router + TypeScript + Tailwind CSS v4 + shadcn/ui + Firebase + framer-motion. Deploy en Netlify.

**Usuarios:** 2 administradores (área de compensaciones) + 50+ colaboradores (empleados internos Ferco). Solo en español.

## Firebase: colecciones

### `users/{uid}`
```ts
{ uid, email, displayName, role: "administrador"|"colaborador",
  area, cargo, createdAt, lastLoginAt }
```

### `requests/{requestId}`
```ts
{ id, requestNumber,               // "COMP-2026-AB3F2C"
  createdBy, creatorName,

  // Campos del formulario (campos con * son obligatorios)
  tipoMovimiento: "incremento"|"promocion"|"ajuste_salarial"|"nueva_plaza"|"otro",  // *
  tipoMovimientoOtro?: string,     // habilitado solo si tipoMovimiento === "otro"
  detalleMovimiento: string,       // *
  nombreSolicitante: string,       // *
  puestoSolicitante: string,       // *
  nombrePersonaEvaluar: string,    // *
  puestoPersonaEvaluar: string,    // *
  pais: "Guatemala"|"El Salvador"|"Honduras"|"México",  // *
  area: string,                    // *
  sucursal?: string,               // opcional
  bonoVariable1?: number,          // opcionales (1-5)
  bonoVariable2?: number,
  bonoVariable3?: number,
  bonoVariable4?: number,
  bonoVariable5?: number,
  justificacion: string,           // *

  stage: "en_analisis"|"en_proceso_aprobacion"|"finalizada"|"cancelada_denegada",
  attachments: [{id, fileName, fileType, fileSize, storageUrl, uploadedBy, uploadedAt}],
  commentCount, createdAt, updatedAt, stageChangedAt, stageChangedBy? }
```

**Lógica condicional del formulario:** cuando `tipoMovimiento === "otro"`, se muestra dinámicamente un campo de texto `tipoMovimientoOtro` con `react-hook-form` `watch()`. El schema Zod valida: si `tipoMovimiento === "otro"` entonces `tipoMovimientoOtro` es obligatorio.

### `requests/{id}/comments/{commentId}`
```ts
{ id, requestId, content, authorId, authorName, authorRole,
  parentId?,   // null = raíz, string = respuesta
  attachments?, createdAt, editedAt? }
```

### `notifications/{notificationId}`
```ts
{ id, recipientId, type, requestId, requestNumber, requestTitle,
  fromUserId, fromUserName, newStage?, commentPreview?,
  read: boolean, createdAt }
```

**Índices Firestore requeridos:**
- `notifications`: `(recipientId, read, createdAt DESC)`
- `requests`: `(createdBy, stage, createdAt DESC)`
- `requests`: `(stage, createdAt DESC)`

## Reglas de notificaciones

| Evento | Quién dispara | Destinatario | Tipo |
|---|---|---|---|
| Nueva solicitud creada | `RequestForm.tsx` | Todos los admins (query `role=="administrador"`) | `new_request` |
| Cambio de etapa | `KanbanBoard.tsx` onDragEnd | `request.createdBy` | `stage_changed` |
| Comentario nuevo (raíz) | `CommentInput.tsx` | Colaborador → admins; Admin → creador | `new_comment` |
| Respuesta a comentario | `CommentInput.tsx` (con parentId) | `parentComment.authorId` | `comment_replied` |

Implementación: `writeBatch()` atómico en `lib/firebase/firestore.ts`. Con 2 admins, el fan-out es trivial (máx 2 writes). Los UIDs de admins se obtienen dinámicamente via query, no hardcodeados.

## Flujo de autenticación

1. Cualquier ruta `(portal)/*` → `AuthGuard` revisa `AuthContext.loading`
2. Sin usuario → redirect a `/login`
3. `LoginForm` llama `signInWithEmailAndPassword()`
4. `onAuthStateChanged` → fetch `users/{uid}` de Firestore → hidrata `role`
5. Redirect según rol: ambos van a `/dashboard` (admin puede arrastrar, colaborador solo ve)
6. Creación de usuarios: admin manual desde Firebase Console o script de seed

> **Importante:** Toda la autenticación es client-side. No usar Next.js middleware para Firebase Auth (incompatible con Netlify sin backend custom).

## Tema y diseño

- **globals.css:** Variables CSS provistas por el usuario (blanco/oscuro) + color gold `#D4A017` para acento Ferco
- **Logo:** Versión oscura en fondo claro (header), versión blanca en sidebar colapsado o dark mode
- **Animaciones framer-motion:**
  - Kanban: columnas con `staggerChildren` al cargar
  - Cards: `whileHover={{ y: -2, boxShadow }}`

## Puntos críticos / gotchas

- **Drag-and-drop race condition:** Con 2 admins es tolerable. Usar optimistic UI + rollback si falla el write.
- **Firebase Storage CORS:** Configurar CORS en el bucket antes del primer deploy (`gsutil cors set cors.json gs://bucket`).
- **Uploads antes del doc:** Subir archivos a Storage primero, luego crear el documento Firestore con las URLs ya pobladas.
- **commentCount:** Usar `writeBatch()` para escribir comentario + incrementar contador atómicamente.
- **Tailwind v4 + shadcn:** Usar `@theme` directive en globals.css para colores Ferco, no en tailwind.config.ts.
- **Firebase en App Router:** Todo Firebase es client-side. Marcar componentes con `"use client"`. No importar Firebase en Server Components.
- **Formulario campos pendientes:** Los campos exactos del formulario serán confirmados con las capturas de pantalla del usuario. El esquema Zod se actualiza en ese momento.
